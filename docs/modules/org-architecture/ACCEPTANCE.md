# 组织架构管理验收标准

1. 技术管理员具备 `org.architecture.manage` 时可访问 `/tech/org`；无权限身份访问被路由和服务端双重拒绝。
2. 新增组织后正式表出现一个节点，架构版本加一，技术端与企业通讯录刷新后读取同一节点；重复同一幂等键不重复创建。
3. 节点更新携带旧 `version_no` 时返回 409；把节点移动到自身或后代返回 400；合法移动同步更新下级路径。
4. 仍有下级或有效任职的组织不能删除；可删除节点执行软删除并保留变更、版本和安全审计。
5. 委派 `org.architecture.edit` 后，工作端身份可进入公司架构管理；撤销后下一次会话权限投影即不再允许访问。
6. 草稿创建复制当前正式树；保存后生成新增、修改、移除差异；草稿保存不会改变正式组织或企业通讯录。
7. 草稿创建人不能审批自己的草稿；驳回必须填写原因；状态转换不合法或版本过期返回明确错误。
8. 草稿基线落后于正式版本时提交或发布返回 409；重新创建/合并新草稿后方可继续。
9. 发布在同一事务中完成快照校验、正式组织写入、版本追加和草稿标记；任一约束失败时正式组织无部分残留。
10. 企业通讯录仅返回当前有效任职的姓名、工号、组织与岗位，响应中不包含手机号、证件号或密文原值。
11. 三张新增表启用租户 RLS；跨租户 ID 查询不能读取或修改数据。
12. Java 单元测试、Spotless、Flyway 版本检查、前端 lint/typecheck/unit/build、重复率和死代码门禁全部通过。
