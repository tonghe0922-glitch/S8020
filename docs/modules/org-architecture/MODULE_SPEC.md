# 组织架构管理模块规格

## 目标与范围

本模块把技术端直接配置、工作端草稿审批发布和全员企业通讯录连接为同一个闭环。正式组织的唯一事实源始终是 `org.organization`；`org.architecture_draft` 只保存尚未发布的服务端草稿，不能被运行时权限、通讯录或其他业务模块当作正式组织使用。

范围包括：

- 技术端 `/tech/org`：正式组织树查询、节点新增、乐观锁更新、级联启停、受保护软删除，以及跳转到既有组织—模块授权页；
- 工作端 `/center/03/02/09`：草稿创建、全量快照编辑、变更清单、提交、审批、驳回、发布、废弃；
- 工作端 `/contacts/architecture` 与 `/contacts/directory`：正式组织树和有效任职通讯录只读查询；
- 数据库版本、变更快照、幂等回执、RLS、权限目录和审计联动。

## 非范围

- 不在公开源码中固化真实员工姓名、手机号、证件号或完整人员名单；
- 不新增技术端/工作端平行组织主表；
- 不在本模块直接实现手机号码解密或敏感字段明文授权；
- 不替代现有 `iam.org_module`、`iam.position_role` 和会话权限投影。

## 用户与业务对象

| 用户 | 入口 | 核心能力 |
|---|---|---|
| 技术管理员 | 技术端组织架构 | 直接维护正式组织、启停/删除、进入模块授权 |
| 组织维护人员 | 工作端公司架构管理 | 编辑自己的草稿、生成差异并提交 |
| 审批人 | 工作端公司架构管理 | 查看待审批草稿、通过或驳回；禁止自审 |
| 发布人 | 工作端公司架构管理 | 发布已审批草稿 |
| 普通员工 | 企业通讯录 | 查看正式组织和有效任职，不返回敏感联系方式 |

## 页面与动作

### 技术端

- 组织树按 `path / sort_no / org_code` 排序，展示类型、状态、编码、成员数；
- 右侧表单维护名称、编码、类型、上级、状态、编制、负责人 ID、排序和说明；
- 更新采用节点 `version_no` 乐观锁；移动节点时同步重写下级路径，并拒绝移动到自身后代；
- 软删除前检查直接下级和有效任职；
- 所有写接口必须提供 `Idempotency-Key`。

### 工作端

状态机：`DRAFT → PENDING → APPROVED → PUBLISHED`；驳回为 `PENDING → REJECTED → DRAFT`；未提交草稿可废弃为 `ABANDONED`。

- 草稿创建时复制当前正式组织快照并记录 `base_version`；
- 保存草稿重新计算相对正式组织的 `ADDED / UPDATED / REMOVED` 差异；
- 提交与发布均要求草稿基线仍等于当前正式版本；
- 草稿创建人不能审批自己的草稿；
- 发布事务内完成快照校验、正式表写入、版本追加和草稿状态变更；任何一步失败整体回滚。

### 企业通讯录

- 查询正式组织及当前有效任职；
- 默认只返回姓名、工号、组织、岗位，不返回手机号、证件号等字段；
- 发布或技术端直接变更后刷新即可读取最新正式表。

## 字段与校验

- 组织类型：`MANAGEMENT / DIRECT / COMPANY / CENTER / DEPARTMENT / GROUP`；
- 组织状态：`ACTIVE / INACTIVE`；
- 编制人数与版本号必须非负；
- 同租户有效组织编码唯一；
- 草稿快照必须至少有一个根节点，ID/编码唯一，上级存在且无环；
- 职责说明最多 2,000 字；草稿标题最多 160 字；幂等键最多 160 字。

## 权限与数据范围

服务端以 IAM 授权快照为安全边界，前端隐藏按钮仅作体验优化。正式表、草稿表、版本表和变更表均受租户 RLS 保护，所有仓储操作运行在 `TenantTransactionRunner` 写入的数据库安全上下文中。

## 状态与异常

| 场景 | 响应 |
|---|---|
| 节点/草稿不存在 | 404 `ORG_ARCHITECTURE_NOT_FOUND` |
| 乐观锁或草稿基线过期 | 409 `ORG_ARCHITECTURE_STALE_VERSION` |
| 编码冲突/数据库约束冲突 | 409 `ORG_ARCHITECTURE_CONFLICT` |
| 层级环、非法类型、在岗成员删除等 | 400 `ORG_ARCHITECTURE_INVALID` |
| 权限不足 | 403（统一安全异常合同） |

## 通知与审计

- API 使用 `JdbcSecurityAuditService.recordConfigurationChange` 写入前后快照；
- 业务幂等与回执写入 `org.architecture_change`；
- 事件码：`ORG_NODE_CREATE/UPDATE/TOGGLE/DELETE`、`ORG_DRAFT_CREATE/UPDATE/SUBMIT/REVIEW/PUBLISH/ABANDON`；
- 本次实现以同库直读保证跨端即时一致；Redis 广播属于后续性能优化，不得改变单一事实源。

## 未决问题

- 负责人字段当前接收员工 UUID；待人员选择器组件稳定后替换手工录入；
- 手机号明文展示必须另建敏感字段权限、用途记录和访问审计，不在当前接口中放宽；
- 真实 59 节点由部署侧受控导入，不提交含真实人员姓名的公开种子。
